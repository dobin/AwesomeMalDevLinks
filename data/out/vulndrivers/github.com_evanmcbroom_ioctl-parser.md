# IOCTL Parser

[Permalink: IOCTL Parser](https://github.com/EvanMcBroom/ioctl-parser#ioctl-parser)

[![MIT License](https://camo.githubusercontent.com/f48f8d6cf609f5b181b9c3218a85175fe8a5809c7ea400347f39697a5d55065d/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f6c6963656e73652d4d49542d626c75652e7376673f7374796c653d666c6174)](https://github.com/EvanMcBroom/ioctl-parser/blob/master/LICENSE.txt)[![AppVeyor](https://camo.githubusercontent.com/011cea7b475c1cbcff05c11045bc9424fd9af72f4b51876161e24df06c558ee5/68747470733a2f2f696d672e736869656c64732e696f2f6170707665796f722f6275696c642f4576616e4d6342726f6f6d2f696f63746c2d7061727365723f6c6f676f3d4170705665796f72)](https://ci.appveyor.com/project/EvanMcBroom/ioctl-parser/)

A simple tool for parsing and identifying IO control (IOCTL) values and their subcomponents.
The structure of an IOCTL value is documented on MSDN.1

[![IOCTL Parser](https://github.com/EvanMcBroom/ioctl-parser/raw/master/screenshot.png)](https://github.com/EvanMcBroom/ioctl-parser/blob/master/screenshot.png)

Name identification for devices and functions are supported by using an embedded offline copy of the values on the "Windows IOCTL Reference" website.2
The tool can support identifying additional device and function names by passing configuration files as arguments.
If you are interested in doing this, please use the structure of the [provided example file](https://github.com/EvanMcBroom/ioctl-parser/blob/master/example.ini) or the [embedded configuration file](https://github.com/EvanMcBroom/ioctl-parser/blob/master/resources/IOCTLs.ini) as a reference.

## Building

[Permalink: Building](https://github.com/EvanMcBroom/ioctl-parser#building)

IOCTL Parser requires [CMake](https://cmake.org/) and
[Qt 6.5 LTS](https://wiki.qt.io/Qt_6.5_Release) to build.

```
cd builds
cmake .. -A x64 -DCMAKE_PREFIX_PATH=C:\Qt\<version>\<compiler>\lib\cmake
cmake --build . --config Release
```

IOCTL Parser may be packaged with `cpack` after it's built if desired.
